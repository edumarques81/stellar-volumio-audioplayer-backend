Wire the pure `Collapse` function from Plan 02-01 into both places the backend turns MPD's raw
`list artist` values into an artist list: the SQLite cache builder (`buildArtists`, the path
`CachedService.GetArtists` uses in production) and the MPD-direct fallback (`Service.GetArtists`,

under every code path — not just the common one. This mirrors the DATA-04 precedent from Phase 1
("not only in GetAlbumTracks... everywhere").

Purpose: this is the actual user-visible fix for ARTIST-01/02/03 — after this plan, MPD's 124 raw
`list artist` values collapse into far fewer real-performer rows, with no blank row, wherever an
artist list is served from.
Output: `buildArtists` and `Service.GetArtists` both collapse+merge; unit tests prove the merge
(15 Pavarotti variants → 1 row, summed counts) and the empty-row suppression.
</objective>

```
func (s *Service) GetArtists(req GetArtistsRequest) ArtistsResponse {
	artistNames, err := s.mpd.ListArtists()   // raw names, []string
	...
	for _, name := range artistNames {
		if name == "" { continue }
		if req.Query != "" && !strings.Contains(strings.ToLower(name), queryLower) { continue }
		albumCount := 0
		if albumInfos, err := s.mpd.FindAlbumsByArtist(name); err == nil { albumCount = len(albumInfos) }
		artists = append(artists, Artist{Name: name, AlbumCount: albumCount})
	}
	sort.Slice(artists, ...)  // unchanged, still alphabetical on the final Name
	// pagination below is unchanged
}
```
`Artist` (internal/domain/library/types.go:54): `{Name string, AlbumCount int, AlbumArt string}` —
no ID field, so this is a pure display-value rename; no wire-contract change.

Note the pre-existing, OUT-OF-SCOPE quirk this plan does not fix: `FindAlbumsByArtist(artist)`
queries MPD's `AlbumArtist` tag (`list album albumartist <artist>`), not the raw `Artist` tag being
iterated — so per-raw-name counts were already sometimes wrong before this plan (e.g. querying with
the full "Herbert von Karajan  Wiener Philharmoniker" string already returns 0, since the real
AlbumArtist tag is "Herbert von Karajan"). This plan sums whatever counts the existing calls return;
it does not change count *accuracy*, only *which name* the counts are attributed to. Count accuracy
for collapsed identities is Phase 3's ARTIST-04 territory (drill-down), not this phase's scope.
