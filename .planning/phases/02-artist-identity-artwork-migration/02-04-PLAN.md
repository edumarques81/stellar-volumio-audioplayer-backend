    installs — 9.4.0 already on the Pi) implementing a difference-hash (dHash) perceptual matcher:
    `dhash(image_bytes, hash_size=8)` converts to grayscale, resizes to `(hash_size+1, hash_size)`
    (9x8), compares each row's horizontally-adjacent pixel pairs to produce a `hash_size*hash_size`
    (64-bit) integer hash; `hamming(a, b)` returns `bin(a ^ b).count("1")`. The script has two modes:
    `--calibrate` and the default (match). (4) Run `--calibrate` FIRST, before trusting any match —
    this step is MANDATORY, not optional: pick 6-10 albums that currently HAVE `artwork_id` set
    (`SELECT id, first_track FROM albums WHERE artwork_id IS NOT NULL AND artwork_id != '' LIMIT 10`),
    and for each, fetch its cover via `GET localhost:3000/albumart?path=<first_track>` (local,
    network-free) AND read the linked artwork file directly from `artwork.file_path` for that album's
    `artwork_id` (the enrichment-fetched cover) — compute the Hamming distance between the two hashes
    for each pair. This is the empirical "same album, two different source images" distance
    distribution (analogous to what matching an orphan to its true album will look like, since orphans
    also came from a different source than `/albumart`). Also compute a handful of CROSS pairs
    (one album's `/albumart` hash vs a DIFFERENT album's linked artwork hash) as the "different album"
    negative distribution. Print both distributions (min/max/mean) and choose a threshold that clearly
    separates them (document the exact chosen number and both distributions in the evidence file — do
    not hardcode a threshold without running this step live). (5) Run the default (match) mode: for
    each of the ~40 albums with no artwork link, fetch its `/albumart` cover and hash it; for each of
    the 38 orphan files (via `artwork.file_path` directly — already absolute paths, no
    extension-guessing needed), hash it. For each orphan, find its smallest-Hamming-distance album
    candidate; accept the match only if that distance is `<=` the calibrated threshold AND the gap to
    the SECOND-smallest-distance candidate for that orphan is `>=` a minimum gap (e.g. 4 bits) —
    reject and flag as "ambiguous" otherwise, rather than guessing. Process orphans in ascending
    order of their own best distance so a given album can only be claimed by its best-matching orphan;
    if an orphan's best album is already claimed, re-evaluate against its remaining candidates and
    their gap. Orphans with no candidate under the threshold are "unmatched", left untouched (D-09) —
    per the ROADMAP's own "toward 0" success bar (not "to 0"), this is a correct, honest outcome, not
    a shortfall. (6) Write the dry-run report (orphan artwork id, orphan file, matched album id +
    title + album_artist, Hamming distance, status: matched / ambiguous / unmatched) to
    `.planning/phases/02-artist-identity-artwork-migration/evidence/orphan-match-report-<timestamp>.txt`.
    (7) For ONLY the "ambiguous" cases (not all 38), optionally view the orphan image and the
    candidate album covers with the Read tool as a bounded, secondary tie-breaker, and note the
    outcome — this is the one place any manual visual inspection happens, and it is scoped to the
    genuinely unclear cases only.
  </action>
