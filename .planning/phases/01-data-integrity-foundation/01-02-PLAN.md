<objective>
Hardens the one real MPD read call site that needed it (`GetAlbumDetails`, D-04/D-10) and wires the
DATA-02 skipped/untagged observability signal end-to-end from MPD through the cache to the
Socket.IO wire contract.

Purpose: `GetAlbumDetails` in `internal/infra/mpd/client.go` is the single function behind four
different browse paths -- `GetAlbums`, `GetArtistAlbums` (both in `internal/domain/library/service.go`),
the cache builder's `buildAlbums` (via `mpdDataProviderAdapter` -> `LibraryMPDAdapter` ->
`mpd.Client.GetAlbumDetails`), and `internal/domain/localmusic/service.go`'s album browsing (via a
third adapter, `mpdClientAdapter` in `cmd/stellar/main.go`, which also forwards straight to
`mpd.Client.GetAlbumDetails`). Hardening this one function against `._` junk therefore satisfies
D-10's "at minimum GetAlbumDetails, GetArtistAlbums, and the cache builder paths" for all four
consumers without touching three different domain-level interfaces -- no signature change is needed
because `GetArtistAlbums`/`GetAlbums`/`buildAlbums` never see raw song attrs, only the already-grouped
`AlbumDetails` this function returns.

`ListAlbumsInBase` (mpd/client.go:644) has the identical duplicated grouping logic but is confirmed
dead code -- `grep -rn "\.ListAlbumsInBase(" internal cmd` (excluding tests) shows exactly one call
site, the adapter definition itself, with zero live callers. It is NOT touched by this plan: fixing
an unreachable code path is not a DATA-04 requirement and would inflate this plan's scope with no
observable benefit.

DATA-02's skipped-count is deliberately NOT threaded through `GetAlbumDetails`'s return signature --
doing so would force a signature change across `library.MPDClient`, `localmusic.MPDClient`, and
`cache.MPDDataProvider` (three independently-declared interfaces plus three adapters plus every test
mock), a large mechanical blast radius for a value only the cache builder needs. Instead, `cache.MPDDataProvider`
gains one new, additive method (`CountUntagged`) that re-scans a basePath via the already-existing
`SearchByBase` and applies `musicfile.CountUntagged` -- isolated to the cache package's own interface,
touching nothing outside it.

Output: hardened `GetAlbumDetails`, a persisted `skipped_count` cache-meta value refreshed on every
`FullBuild`, `CacheStats.SkippedCount`, and the Socket.IO + wire-contract-doc plumbing to surface it.
</objective>

  func (c *Client) GetAlbumDetails(basePath string) ([]AlbumDetails, error) {
    ...
    songs, err := c.client.Command("search base %s", basePath).AttrsList("file")
    ...
    albumMap := make(map[string]*AlbumDetails)
    for _, song := range songs {
      album := song["Album"]
      artist := song["AlbumArtist"]
      if artist == "" { artist = song["Artist"] }
      if album == "" { continue }               // becomes the "skipped" counter, AFTER a resource-fork check
      filePath := song["file"]
      directory := filePath
      if idx := strings.LastIndex(directory, "/"); idx > 0 { directory = directory[:idx] }
      key := album + "\x00" + artist + "\x00" + directory
      if _, exists := albumMap[key]; !exists {
        albumMap[key] = &AlbumDetails{Album: album, AlbumArtist: artist, FirstTrack: filePath,
          Format: song["Format"], Genre: NormalizeGenre(song["Genre"])}
      }
      details := albumMap[key]
      details.TrackCount++
      if dur, err := strconv.Atoi(song["Time"]); err == nil { details.TotalTime += dur
      } else if dur, err := strconv.ParseFloat(song["duration"], 64); err == nil { details.TotalTime += int(dur) }
    }
    var albums []AlbumDetails
    for _, details := range albumMap { albums = append(albums, *details) }
    return albums, nil
  }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MPD -> backend | Song attribute maps from `search base` queries feed groupAlbumDetails; semi-trusted (physically-owned SSD content). |
| Backend -> Socket.IO clients | SkippedCount flows to three client types (LCD, iOS, legacy Volumio Connect apps) over the existing `pushLibraryCacheStatus` event. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Tampering | groupAlbumDetails | mitigate | Resource-fork check runs before the album=="" check so junk files can never be miscounted as "untagged real songs"; covered by table-driven test case (c). |
| T-01-04 | Information Disclosure | CacheStatusResponse.SkippedCount | accept | Plain integer count, no filenames or paths exposed; same trust level as existing AlbumCount/ArtistCount fields already on this event. |
| T-01-05 | Denial of Service | Builder.buildSkippedCount | accept | Adds one SearchByBase MPD query per basePath (max 3), only during FullBuild (infrequent, not a hot request path); errors are logged and non-fatal, matching the existing buildRadioStations pattern. |
| T-01-06 | Repudiation | cache_meta "skipped_count" row | accept | Overwritten wholesale on every successful FullBuild via the existing setMeta upsert pattern; no history needed for a point-in-time gauge. |
</threat_model>
