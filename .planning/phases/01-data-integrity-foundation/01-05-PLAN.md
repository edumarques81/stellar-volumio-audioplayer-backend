<objective>
Deploy the Plan 01-01 / 01-02 hardening to the Pi, then run a live regression test for ROADMAP Phase
1 success criterion 4: copying a `._`-prefixed file onto the SSD and rescanning must not change any
album's track count or any artist's album count. Extends `deploy/verify-data-integrity.sh` (from
Plan 01-04) with this check so it is repeatable after any future MPD/backend change, not a one-off.

Purpose: Plan 01-01/01-02 proved the fix with unit tests against synthetic MPD attrs (no live MPD
required). This plan proves the same property against the REAL, deployed backend and REAL MPD
indexing behavior, which unit tests cannot fully substitute for (real MPD's FLAC/DSF decoders may
handle malformed resource-fork bytes differently than a mocked `mpd.Attrs` slice assumes). Per this
project's standing practice ("Verification is done by the agent on the real Pi, not handed back as
QA" -- CONTEXT.md), this closes the loop live.

The regression test writes one small throwaway `._`-prefixed placeholder file into
`/mnt/ssd/Music` -- not real content, and not a copy of anything user-created; it is cleaned up
immediately after the check. Per the workspace constraint "no writes to `/mnt/ssd/Music` without
explicit per-operation confirmation," this plan gates that specific write behind a checkpoint before
it happens, even though the write is transient and disposable (same category as the `._` files
Plan 01-04 just removed).

Output: hardened backend running on the Pi; `deploy/verify-data-integrity.sh` gate I3 added and
passing.
</objective>
