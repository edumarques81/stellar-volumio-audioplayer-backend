<objective>
Enumerate every macOS AppleDouble (`._`) resource-fork file under `/mnt/ssd/Music` on the live Pi,
write the exact list to a durable manifest, and get explicit user confirmation before any deletion
happens (D-03). This plan performs NO destructive action -- it is read-only enumeration plus a
checkpoint. Deletion is Plan 01-04, which consumes the manifest this plan produces.

Purpose: D-01 chose "delete `._` files from the SSD at source" over backend-only filtering, because
filtering alone leaves MPD's own `mpc stats` permanently wrong. D-02 established these files are
macOS sidecar metadata, not user content -- safe to delete. D-03 requires showing the user the exact
file list before deleting anything under `/mnt/ssd/Music`, which this project's constraints treat as
irreplaceable masters.

**Load-bearing discovery from live verification (2026-08-11, this planning session):** `/mnt/ssd` is
mounted **read-only** (`mount` shows `ro,relatime,uid=111,gid=29,...`; `/etc/fstab` has
`UUID=D43D-7F5C /mnt/ssd exfat ro,nofail,uid=mpd,gid=audio,...`). This was NOT previously surfaced in
CONTEXT.md or PROJECT.md's baseline. `sudo blockdev --getro /dev/sda1` returns `0` -- the USB SSD is
NOT hardware write-protected, so the `ro` is a software mount option only, and `sudo -n true`
succeeds (passwordless sudo on this appliance) -- a temporary `mount -o remount,rw /mnt/ssd` /
`mount -o remount,ro /mnt/ssd` round-trip is mechanically available and is how Plan 01-04 will
perform the actual deletion. This plan's checkpoint task explicitly surfaces this mechanism to the
user before they approve, since it is new information not covered by the original D-01/D-03
decisions as recorded.

Live counts as of this session (drift from the CONTEXT.md/PROJECT.md baseline noted -- treat the
live numbers as authoritative): `mpc stats` currently reports 1380 songs / 122 artists / 58 albums.
Restricting `find` to audio extensions (flac/wav/dsf/dff/mp3/m4a/ape/wv/aiff/alac), there are 803
real audio files and 699 `._`-prefixed audio-extension files under `/mnt/ssd/Music` -- plus
additional non-audio `._` siblings (jpg/pdf/DS_Store/directory-name ghosts) that MPD never indexed
and this plan will also enumerate for a complete cleanup, since D-02 established ALL `._` files are
disposable, not just the audio-extension ones.

Output: a manifest file on the Pi at a stable path, and explicit user approval to proceed to
deletion.
</objective>
