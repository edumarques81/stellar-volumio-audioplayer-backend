## Phase Goal

**As a** listener browsing the library on the LCD or the iPhone app, **I want to** see every real
album that physically exists on the SSD (and know immediately if data ever goes missing again),
**so that** I can find and play any song without hitting a silent, unexplained dead end.

*Note on provenance:* ROADMAP.md's Phase 1 `**Goal:**` line is not itself written in
As-a/I-want-to/so-that form (it reads as an outcome statement: "MPD's database and every backend
browse path reflect only real audio files, and any future data gap is visible rather than silently
dropped"). The user story above is derived directly from that line plus PROJECT.md's Core Value
statement and this phase's 4 ROADMAP success criteria -- no new scope was invented. If strict
provenance matters, run `/gsd mvp-phase 1` to formalize the ROADMAP goal line itself; this plan set
proceeds without blocking on that, since Phase 1 is data-integrity/infrastructure work rather than a
new user-facing feature, and the 4 success criteria already fully constrain what "done" means.

<objective>
Create the single shared predicate package for macOS AppleDouble (`._`) resource-fork detection
that every later hardening task in this phase depends on, and prove it via the one existing call
site that already does this filtering inline (`GetAlbumTracks`).

Purpose: D-11 requires one shared helper instead of repeated inline `strings.HasPrefix(base, "._")`
checks, so a future MPD read call site cannot forget the filter. This plan defines that contract
first (interface-first ordering) so Plan 01-02 can build on it without re-deriving the predicate.

Per the corrected package location (see `<critical_corrections>` in the phase brief — do NOT follow
`01-PATTERNS.md`'s recommendation of `internal/domain/library/filter.go`, which would invert this
codebase's layering): `internal/infra/mpd` imports zero files from `internal/domain` today; if the
helper lived in `internal/domain/library`, `internal/infra/mpd` would have to import a domain
package to use it, and `internal/domain/library` already imports `internal/infra/cache`
elsewhere — that combination would create exactly the layering inversion this codebase avoids
everywhere else. `internal/infra/musicfile` is a new leaf package under `internal/infra` with zero
dependencies, importable by `internal/infra/mpd` (Plan 01-02) and `internal/domain/library` (this
plan) alike, matching the existing `internal/infra/{cache,mpd,paths,...}` sibling pattern.

Output: `internal/infra/musicfile` package (2 exported functions, table-driven tests) and
`GetAlbumTracks` refactored to consume it.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
