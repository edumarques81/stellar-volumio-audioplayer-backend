<objective>
Query MPD live (post-junk-cleanup, so the count is clean) for every real song missing an `Album`
tag, group by folder, derive a recommended `Album`/`AlbumArtist` value per folder from the folder
name and each song's existing `Artist` tag, and write the result as a durable, copy-pasteable
document. Then hand off to the user via a `checkpoint:human-action` -- no CLI/API can write tags into
the user's own tagger, and D-04 forbids the agent from writing tags to `/mnt/ssd/Music` directly.

Purpose: D-05's phase deliverable. D-06 explicitly rejected a folder-name-fallback CODE PATH (the
backend must never infer Album from folder-name string parsing at runtime) -- that is not what this
plan does. This plan derives folder-name-based *recommendations* for a one-time, human-reviewed
document, which is exactly what D-05 asks for; the backend itself still requires an `Album` tag and
still skips (and now counts, per Plan 01-02) untagged real songs.

Output: `.planning/phases/01-data-integrity-foundation/DATA-01-RETAG-RECOMMENDATIONS.md` and a
human-action checkpoint requesting the user retag the listed files.
</objective>
