<objective>
Extend the SQLite cache — the code path the deployed Pi's `library:albums:list` actually serves in
production (cache is populated; `Service.GetAlbums` from 03-03 is only the empty-cache fallback) —
with the same grouping (BROWSE-07) and badging (BROWSE-01/02/03) computed at cache-build time, so a
cache-served album list matches the MPD-direct path byte-for-byte.

Purpose: 03-03 made the MPD-direct path correct. Without this plan, the live Pi (which always has a
populated cache) would keep showing 11 Mahler tiles and unbadged duplicates, because
`CachedService.GetAlbums` reads straight from SQLite rows that `Builder.buildAlbums` writes without
any grouping/badging logic. Computing once at build time (rather than per-query) also avoids
re-running `discgroup`/`dupebadge` over the whole library on every album-list request.

Output: Schema v6 (`badge`, `disc_count` columns on `albums`); `Builder.buildAlbums` groups raw
per-basePath `AlbumDetailsData` via `discgroup.Group`, computes badges across the combined result via
`dupebadge.Compute`, and persists both; `CachedService.GetAlbums` maps them onto `library.Album`.
</objective>
